# 重复性工作：录一次，之后免费回放

同一件事每天都要做时，读这一页。

`browser_macro` 会把一个目标找到的路径录下来，回放时**不调用模型**。回放会针对新的观察结果，按 role + 名称重新定位每一步；
如果最佳匹配太弱或有歧义（`threshold`，默认 `0.7`），就拒绝操作，所以它会明确失败，而不是点错东西。

一件*完全相同地*重复的杂事，不应该永远交给 `browser_goal`：付一次模型费用，`record_stop` 录下来，以后每天 `run` 这个宏。
`params` 会填充文字和 URL 里的 `{{placeholders}}`，这样一个宏就能服务很多天或很多组输入。信任一个宏之前，用 `inspect` 看看录下的步骤。

**回放只适合每次步骤都一样的流程。** 判断一个候选流程，要看它*点的那些文字*是否稳定，而不是看任务是否重复。
每天早上题目和选项都换新的每日问答，不适合回放，应该交给 `browser_goal`：解析器会拒绝而不是去猜，所以宏在那里会安全地、
但毫无用处地失败。按钮每天都在同一位置的签到表单可以回放；答案每天变化的问答不行。
